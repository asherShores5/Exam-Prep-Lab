IAM Role defined in the Security Group is different from the IAM Role that is given access in the Network ACLs
Correct answer

Security Groups are stateful, so allowing inbound traffic to the necessary ports enables the connection. Network ACLs are stateless, so you must allow both inbound and outbound traffic

Rules associated with Network ACLs should never be modified from the command line. An attempt to modify rules from the command line blocks the rule and results in an erratic behavior
Overall explanation

Correct option:

Security Groups are stateful, so allowing inbound traffic to the necessary ports enables the connection. Network ACLs are stateless, so you must allow both inbound and outbound traffic - Security groups are stateful, so allowing inbound traffic to the necessary ports enables the connection. Network ACLs are stateless, so you must allow both inbound and outbound traffic.

To enable the connection to a service running on an instance, the associated network ACL must allow both inbound traffic on the port that the service is listening on as well as allow outbound traffic from ephemeral ports. When a client connects to a server, a random port from the ephemeral port range (1024-65535) becomes the client's source port.

The designated ephemeral port then becomes the destination port for return traffic from the service, so outbound traffic from the ephemeral port must be allowed in the network ACL.

By default, network ACLs allow all inbound and outbound traffic. If your network ACL is more restrictive, then you need to explicitly allow traffic from the ephemeral port range.

If you accept traffic from the internet, then you also must establish a route through an internet gateway. If you accept traffic over VPN or AWS Direct Connect, then you must establish a route through a virtual private gateway.

Question 7Skipped

A user increases the size of an Amazon EBS volume attached to a Windows-based Amazon EC2 instance by using the Amazon EC2 console. After the modification completes, the operating system does not show the additional storage space in the file system.

Which action should a systems administrator take to resolve this issue?
Correct answer

Extend the file system inside the operating system to use the additional disk space.

Create a new partition on the unallocated space and assign it the same drive letter as the existing volume

Detach and reattach the EBS volume to the EC2 instance to refresh the disk configuration

Reboot the EC2 instance to force the operating system to detect the new volume size
Overall explanation

Correct option:

Extend the file system inside the operating system to use the additional disk space.

When an EBS volume is resized, AWS increases the block device size, but the operating system does not automatically extend the partition or file system. The administrator must expand the partition and file system to use the newly available space. On Windows, this is typically done by using Disk Management or the Resize-Partition PowerShell cmdlet. The process does not require detaching the volume or restarting the instance.

Extending the file system is the recommended and simplest way to make the additional capacity available after an EBS volume modification.

via - https://docs.aws.amazon.com/ebs/latest/userguide/recognize-expanded-volume-linux.html

Incorrect options:

Detach and reattach the EBS volume to the EC2 instance to refresh the disk configuration - Detaching and reattaching the volume is not required after modifying its size. Modern EBS volume modifications are applied dynamically without the need to detach the volume. The operating system can detect the new size without reattachment. The missing step is expanding the partition or file system within the OS.

Reboot the EC2 instance to force the operating system to detect the new volume size - Rebooting the instance is not necessary to recognize the new volume size. EBS supports online resizing, and Windows can detect the updated disk size without a restart. Even after a reboot, the file system would still require manual extension. Restarting alone does not resolve the issue.

Create a new partition on the unallocated space and assign it the same drive letter as the existing volume - Creating a new partition on the unallocated space would result in a separate logical volume rather than extending the existing file system. This approach does not expand the current drive. Additionally, Windows does not allow assigning the same drive letter to multiple partitions. The correct action is to extend the existing partition to include the new space.

https://docs.aws.amazon.com/ebs/latest/userguide/recognize-expanded-volume-linux.html

    Periodic: AWS Config runs evaluations for the rule at a frequency that you choose (for example, every 24 hours).

Create two rules, one with configuration change and the other with periodic triggers - This will be a management overhead and hence is not an optimal solution.

At the simplest level, AWS WAF lets you choose one of the following behaviors:

    Allow all requests except the ones that you specify – This is useful when you want Amazon CloudFront, Amazon API Gateway, Application Load Balancer, or AWS AppSync to serve content for a public website, but you also want to block requests from attackers.

This lets you confirm that you didn't accidentally configure AWS WAF to block all the traffic to your website. When you're confident that you specified the correct properties, you can change the behavior to allow or block requests.
