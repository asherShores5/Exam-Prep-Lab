Explanation

Correct selection

Early stopping
Explanation
Early stopping is a regularization technique used during the training of machine learning models to prevent overfitting. By monitoring the model's performance on a validation set and stopping the training process when the performance starts to degrade, early stopping helps in addressing both bias and variance by finding the optimal balance between underfitting and overfitting.

Using a more complex model with more features
Explanation

While complex models may have the capacity to capture intricate patterns in the data, they are also more prone to overfitting and may introduce bias due to the increased complexity. This choice is not the best strategy for addressing both bias and variance in responsible AI.
Correct selection

Cross-validation
Explanation
Cross-validation is a technique used to evaluate the performance of machine learning models by training and testing on multiple subsets of the data. It helps in addressing both bias and variance by providing a more accurate estimate of the model's performance and generalization ability.

Principal Component Analysis (PCA)
Explanation
Principal Component Analysis (PCA) is a dimensionality reduction technique that is not specifically designed to address bias and variance in machine learning models. While PCA can help in reducing the dimensionality of the data and improving computational efficiency, it does not directly tackle the issues of bias and variance.

Question 9Skipped

A global e-commerce company operates applications across multiple AWS regions (us-east-1, eu-west-1, and ap-southeast-1) that require access to database credentials for their Amazon RDS MySQL instances. The security team has mandated that database passwords must be rotated every 30 days without causing application downtime. Additionally, if the primary region (us-east-1) experiences an outage, applications in other regions must be able to immediately access the current valid credentials without manual intervention. The company wants to minimize operational overhead while maintaining consistent secret values across all regions during normal operations.

Which approach should the company implement to meet these requirements?

Create independent secrets in each region with separate automatic rotation schedules, use Amazon EventBridge to synchronize rotation events across regions, and implement application logic to query all three regions simultaneously and select the most recent secret version.
Explanation

Creating independent secrets with separate rotation schedules creates significant operational complexity and risk. The secrets would rotate at different times, causing credential mismatches between regions. Applications could fail if they retrieve credentials from one region that were rotated but haven't been rotated yet in another region. EventBridge cannot directly synchronize rotation events to keep passwords identical. This approach defeats the purpose of having consistent credentials across regions.

Create a primary secret in us-east-1 with automatic rotation enabled, use AWS Step Functions to orchestrate manual copying of the rotated secret to eu-west-1 and ap-southeast-1 after each rotation, and configure CloudWatch alarms to notify operators when replication fails.
Explanation

Using Step Functions for manual orchestration of secret copying adds significant operational overhead and complexity. There would be a delay between rotation in the primary region and replication to other regions, creating a window where applications in secondary regions might fail due to using outdated credentials. CloudWatch alarms for failed replication require manual intervention. This approach doesn't minimize operational overhead and creates potential downtime during rotation windows.
Correct answer

Create a primary secret in us-east-1 with automatic rotation enabled using AWS Lambda, configure the secret to replicate to eu-west-1 and ap-southeast-1 as read replicas, and configure applications to retrieve secrets from their local region with automatic failover to other regions.
Explanation

AWS Secrets Manager supports secret replication across regions. When you enable replication, the primary secret (in us-east-1) automatically synchronizes its value to read-only replica secrets in other regions. When automatic rotation occurs on the primary secret, the new value is automatically propagated to all replicas within seconds. Applications can retrieve secrets from their local region (reducing latency and improving availability), and if one region fails, they can failover to retrieve from replica regions. This provides high availability, automatic rotation, and minimal operational overhead—meeting all requirements.

Store the database credentials in AWS Systems Manager Parameter Store with automatic rotation enabled, use AWS Global Accelerator to route secret retrieval requests to the nearest healthy region, and configure cross-region replication manually using Lambda functions.
Explanation

AWS Systems Manager Parameter Store does not natively support automatic secret rotation like Secrets Manager does. While Parameter Store can store secrets, you would need to build custom rotation logic using Lambda. Parameter Store also doesn't have built-in cross-region replication features. Global Accelerator is for routing network traffic to application endpoints, not for secret retrieval APIs. This solution adds unnecessary complexity and doesn't leverage purpose-built secret management capabilities.
