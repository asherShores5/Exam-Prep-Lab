        bucket = "tf-state-bucket"
        key    = "terraform/krausen/"
        region = "ap-south-1"
      }

terraform plan -refresh=false
Explanation

terraform plan -refresh=false command is used to generate an execution plan without refreshing the state. While refreshing the state is important for state migration, this command does not directly handle the migration process.
Correct answer

terraform init -migrate-state
Explanation

Running terraform init -migrate-state command is the correct choice to complete the state migration while copying the existing state to the new backend. This command initializes the backend configuration and migrates the state to the specified S3 backend.

terraform apply -refresh-only
Explanation

terraform apply -refresh-only command is used to apply changes to the infrastructure with only refreshing the state. It does not specifically handle the migration of the state file to a new backend like the terraform init -migrate-state command does.

terraform state show
Explanation

terraform state show command is used to show the attributes of a specific resource in the Terraform state. It is not the appropriate command for migrating the state file to a new backend.
Overall explanation

Objective 6c - Configure remote state using the backend block

Whenever a configuration's backend changes, you must run terraform init again to validate and configure the backend before you can perform any plans, applies, or state operations. Re-running init with an already-initialized backend will update the working directory to use the new backend settings. Either -reconfigure or -migrate-state must be supplied to update the backend configuration.

When changing backends, Terraform provides the option to migrate your state to the new backend. This lets you adopt backends without losing any existing state.

Objective 6d - Manage resource drift and Terraform state

During a standard terraform plan, Terraform automatically queries your infrastructure providers to refresh the state data in memory. The -refresh flag defaults to true, so you don't need to specify it explicitly for normal operations.

    }

Explanation

This module block incorrectly sources the module from a GitHub repository instead of the Terraform registry. Additionally, it incorrectly assigns the variables var.address_space and var.name to the name and address_space inputs, respectively, which is the opposite of what is required. This configuration does not meet the specified requirements.

    module "vnet" {
      source        = "Azure/network/azurerm"
      version       = ">= 5.0"
      name          = "var.name"
      address_space = "var.address_space"
    }

Explanation

This module block incorrectly specifies the version constraint as >= 5.0 instead of ~> 5.0 to keep it on a 5.x release. Additionally, the name and address_space inputs are not correctly passed from variables, as they are enclosed in quotes, making them string literals instead of variable references.

    module "vnet" {
      source         = "./modules/network"
      version        = "~> 5.0"
      name           = var.name
      address_space  = var.address_space
    }

Explanation

This module block incorrectly sources the module from a local path ./modules/network instead of the Terraform registry. While it correctly specifies the version constraint as ~> 5.0 and passes the name and address_space inputs from variables, it does not meet the requirement of using a public Azure virtual network module from the registry.
Correct answer

    module "vnet" {
      source        = "Azure/network/azurerm"
      version       = "~> 5.0"
      name          = var.name
      address_space = var.address_space
    }

Explanation

This module block correctly sources the public Azure virtual network module from the Terraform registry, specifies a 5.x release with the ~> 5.0 version constraint, and correctly passes the name and address_space inputs from variables var.name and var.address_space, respectively. This configuration meets all the requirements stated in the question.
Overall explanation

Objective 5c - Use modules in configuration

Registry modules use a registry source address and support version constraints. The constraint ~> 5.0 keeps you on 5.x while allowing patch and minor updates. Inputs should be expressions, not quoted strings. Local paths and raw VCS URLs do not use registry-style versioning in the module block.
